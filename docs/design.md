# Design

Written 2026-10-13 from research + spikes. Settled choices and their reasons: `decisions.md`.
Vocabulary: `GLOSSARY.md`.

## 1. The problem in one paragraph
A seed is 256 bits. The world simulates it under Conway's rules on a 64×64 torus for up to 1000 steps. A run
succeeds the first time the target object appears, isolated, anywhere, in any phase and orientation. Searchers
spend an equal budget of evaluations; we compare how often and how fast each one hits (**contest 1**), and, among
seeds that hit, how few live cells the best one needs (**contest 2**).

## 2. Encoding
- **Genome = 16×16 bitstring, row-major, kept as a `Uint8Array(256)`.** Direct encoding: one gene per cell. It is
  the encoding every source in `research/prior-art.md` reports for seed search, and the one an examiner can read.
- Placement: seed copied into the centre of an empty world. Fixed position, so a genome maps to exactly one world.
- Random initialisation at density 0.5, which matches Catagolue's soups — so our random searcher is directly
  comparable to the census.
- Rejected for now: indirect encodings (CPPN/NEAT as in Wolper & Abraham) — more power, much harder to explain
  in a viva, and their own result was that objective search still collapsed to trivial patterns.

## 3. Evaluation and fitness
1. Simulate. Every `SCAN_EVERY` (4) steps, look for the target. Stop early on a hit, on the first repeated state
   (hash of the grid), or at the cap.
2. **Detection:** templates are generated by evolving the canonical object through its period and applying all 8
   symmetries, deduplicated. A match needs the template's cells **and** a one-cell dead ring around them
   (isolation). Only anchors on live cells are tried, which keeps a scan cheap.
3. **Fitness (contest 1):** `1` on a hit; otherwise `1 − bestMismatch / windowSize`, where `bestMismatch` is the
   fewest cells by which any template window ever differed from the world during the run. This partial credit is
   what gives local search and the GA a gradient instead of a flat "no" everywhere. Spike status: implemented in
   `prototypes/PROTOTYPE-race.mjs`; whether it actually guides search is what the race measures.
4. **Fitness (contest 2):** hit is mandatory; among hits, fewer live cells is better:
   `fitness = hit ? 1 + (256 − liveCells) / 256 : partial`. Searchers only (no random seeding contestant).
5. Known risk (prior art): fitness landscapes over CA seeds are chaotic — one flipped cell can rewrite the future.
   Partial credit can be **deceptive** (a near-miss pattern that never becomes the target). The binary-only
   fitness is kept as an ablation to measure whether partial credit helps at all. **(open: Q2)**

## 4. Searchers (common interface)
`run({ evaluate, budget, rng }) → void` — the evaluator counts evaluations and throws when the budget is spent,
so no searcher can overspend. The runner records first-hit evaluation index and best seed.

| Searcher | Move | Notes |
|---|---|---|
| Random | fresh density-0.5 seed each evaluation | the baseline; its hit rate ≈ budget × per-soup rate |
| Hill climbing (RMHC) | flip **one** random bit; accept if fitness ≥ current (neutral moves allowed); restart after N non-improving | the variant that beat a GA ~10× in Mitchell, Holland & Forrest (NIPS 1993) — must be a real rival. (The spike used 1–3 flips; the build uses one.) |
| Simulated annealing | same move; accept worse with `exp(Δ/T)`, T geometric 0.05 → 0.002 over the budget | covers the heuristic-search unit |
| Genetic algorithm | pop 20, tournament k=3, **block crossover** (rectangle from parent B), bit-flip mutation 1/256, elitism 2 | headline; operators in `search/ga-operators.js` |
| GA, uniform crossover | as above, per-cell coin-flip crossover | ablation: does keeping 2D blocks together matter? |

Parameters above are spike defaults, to be tuned once, then frozen before the experiment.

## 5. Experiment protocol
- Targets: the **ladder** (§6). Budgets per rung so random sits in its interesting zone (it hits sometimes).
- **Runs:** ≥ 20 independent RNG seeds per (searcher, target). Same seeds across searchers.
- **Metrics:** success rate within budget; evaluations to first hit (median, censored at budget);
  best fitness reached. Contest 2: fewest live cells among hitting seeds.
- **Reporting:** success-rate bars with 95% Wilson intervals; first-hit survival curves (fraction of runs still
  without a hit vs evaluations spent) — the clearest single chart for "who gets there faster".
- Honesty rules: one lucky run proves nothing; report losses to random; freeze parameters before the final runs.

## 6. Target ladder (see `research/targets.md`, measured rates in `research.md`)
glider (sanity) → LWSS / pulsar → HWSS → pentadecathlon → figure eight (stretch). Gosper gun is out: zero
occurrences in 3.4×10¹⁴ Catagolue soups.

## 7. Architecture
```
engine/   life.js (step, hash, place seed) · objects.js (canonical patterns) · detect.js (templates, match,
          mismatch) — pure ES modules, no DOM, shared by browser and Node
search/   random.js · hill.js · anneal.js · ga.js — all take (evaluate, budget, rng)
experiment/ evaluator.js (budget owner, fitness) · runner.js (grid of runs → results JSON)
cli/      run-experiments.mjs — Node, worker_threads across cores, writes results/*.json
web/      index.html · ui.js · worker.js (runs a searcher off the main thread, posts progress)
tests/    node:test — known-answer tests for engine + detection + budget accounting
```

## 8. Stack and dependencies
- **Vanilla JS, ES modules, no build step, no framework.** Every line is explainable in a viva; nothing to
  install to read the code. Canvas 2D for the grid.
- **Runtime dependencies: none planned.** Charts hand-drawn on canvas/SVG (two chart types only). If that costs
  too much time, fall back to **uPlot** (single small file, vendored into `web/vendor/`, no CDN at runtime).
  **(open: Q7)**
- **Dev:** Node 22 (installed, v22.22.3) for headless experiments and `node --test` (built in — no Jest/Vitest).
- **Serving locally:** ES modules need http, not `file://`. A ~15-line `node:http` static server in `cli/serve.mjs`
  (no dependency). Deploy later: GitHub Pages or Cloudflare Workers static.
- **Performance:** spike measured ~111 evaluations/s (lifespan only) and ~40/s (with single-target detection)
  per core in plain JS. Experiments run in Node across 22 cores via worker_threads; the page runs one search in a
  Web Worker so the UI stays live. Bit-packed simulation (32 cells per int) is the known 10×+ speed-up if needed —
  not planned unless measurements demand it.

## 9. Out of scope (this deadline)
Rule evolution (B/S genomes), glider-gun targets, neural CA, indirect encodings, the evolved-creatures game.
